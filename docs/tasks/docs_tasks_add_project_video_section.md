# Задача: добавить видеоблок между секциями «Ценность актива» и «Концепция»

## 1. Контекст проекта

Проект: `sk-develop`

Сайт: `https://снк-девелоперскийпроект.рф`

Репозиторий:

```text
https://github.com/asruzela-sketch/sk-develop
```

Текущий стек:

- Vite;
- React 18;
- TypeScript;
- Tailwind CSS;
- shadcn-ui / Radix UI;
- React Router;
- статический production-деплой через Docker и Nginx.

Перед началом работы обязательно изучить:

```text
AGENTS.md
AI_CONTEXT.md
DEPLOYMENT.md
TODO.md
```

Соблюдать текущие архитектурные ограничения проекта:

- не добавлять backend;
- не добавлять базу данных;
- не менять фреймворк;
- не переписывать проект на Next.js;
- не менять существующий дизайн за пределами нового блока;
- не добавлять новые зависимости без реальной необходимости.

---

## 2. Цель задачи

Добавить на главную страницу новый видеоблок между существующими секциями:

```text
«Ценность актива»
↓
новый видеоблок
↓
«Концепция»
```

Исходное видео находится в проекте или будет предоставлено по пути:

```text
sk-develop/video
```

Нужно встроить видео так, чтобы:

- оно визуально соответствовало текущему дизайну сайта;
- не ухудшало скорость загрузки страницы;
- корректно работало на мобильных устройствах;
- не загружало исходный файл целиком без необходимости;
- не создавало горизонтального скролла;
- не ломало текущую структуру и существующие секции.

---

## 3. Архитектурное решение

### 3.1. Не использовать GIF

Не конвертировать видео в GIF.

Причины:

- GIF обычно весит значительно больше оптимизированного видео;
- GIF хуже сохраняет качество;
- GIF не поддерживает нормальное управление воспроизведением;
- GIF создаёт лишнюю нагрузку на мобильный интернет и браузер.

### 3.2. Форматы видео

Подготовить оптимизированные версии:

```text
public/video/sk-develop.webm
public/video/sk-develop.mp4
```

Приоритет:

1. WebM — основной современный формат;
2. MP4 H.264 — fallback для совместимости.

Исходный тяжёлый файл не должен попадать в production-сборку и Git-репозиторий.

Если исходник действительно весит около 50 ГБ, использовать его только как мастер-файл для конвертации.

### 3.3. Рекомендуемые параметры экспорта

Для desktop-версии:

- разрешение: не выше 1920×1080;
- кодек MP4: H.264;
- кодек WebM: VP9 или AV1, если конвертация не создаёт проблем;
- частота кадров: сохранить исходную, но не выше 30 fps без необходимости;
- целевой битрейт: ориентировочно 2–5 Мбит/с;
- без лишней аудиодорожки в версии для autoplay.

Для mobile при необходимости подготовить отдельную версию:

```text
public/video/sk-develop-mobile.webm
public/video/sk-develop-mobile.mp4
```

Рекомендуемые параметры:

- разрешение: 720p или близкое к фактическому размеру блока;
- битрейт: ориентировочно 1–2.5 Мбит/с;
- размер файла желательно удержать в пределах нескольких мегабайт.

Не использовать точные значения механически. Сначала оценить длительность, исходное разрешение и визуальное качество.

### 3.4. Постер

Подготовить постер первого кадра или подходящего выразительного кадра:

```text
public/video/sk-develop-poster.webp
```

Постер должен:

- отображаться до начала воспроизведения;
- иметь небольшой размер;
- соответствовать соотношению сторон видео;
- не содержать случайного или технического кадра.

---

## 4. Поведение видео

### 4.1. Базовый вариант

Видео должно:

- запускаться автоматически, когда блок появляется в области просмотра;
- воспроизводиться без звука;
- иметь атрибуты `muted`, `playsInline` и `loop`;
- останавливаться, когда блок выходит далеко за пределы viewport;
- не запускать загрузку полного файла сразу при открытии страницы;
- использовать `preload="metadata"` или более экономичный режим;
- учитывать системную настройку `prefers-reduced-motion`.

Для пользователей с `prefers-reduced-motion: reduce`:

- не запускать автоматическое воспроизведение;
- показывать постер;
- разрешить запуск вручную.

### 4.2. Музыка

Не включать музыку автоматически.

Причины:

- современные браузеры блокируют autoplay со звуком;
- внезапный звук раздражает пользователей;
- значительная часть посетителей откроет сайт с телефона;
- фоновая музыка снижает контроль пользователя над страницей.

Если аудиодорожка важна для презентации объекта, реализовать один из вариантов:

#### Предпочтительный вариант

- autoplay-версия видео без звука;
- поверх видео небольшая ненавязчивая кнопка:
  - «Включить звук»;
  - после нажатия звук включается;
  - состояние кнопки визуально меняется;
  - пользователь может снова выключить звук.

#### Допустимый упрощённый вариант

- видео всегда без звука;
- без отдельного управления аудио.

Не добавлять собственную сложную медиасистему.

## 5. UI нового блока

Создать отдельный компонент, например:

```text
src/components/ProjectVideoSection.tsx
```

Точное имя можно адаптировать под текущий стиль именования компонентов.

Блок должен:

- занимать ширину, согласованную с соседними секциями;
- использовать существующие контейнеры, отступы, радиусы и визуальные правила;
- не добавлять новый визуальный стиль;
- выглядеть как часть текущего сайта;
- иметь корректный фон и вертикальные отступы;
- не менять дизайн секций «Ценность актива» и «Концепция».

Если в текущем дизайне уместен заголовок, использовать нейтральный вариант:

```text
Проект в деталях
```

Однако сначала проверить композицию страницы. Если видео лучше работает без заголовка, не добавлять его ради формальности.

### 5.1. Соотношение сторон

- сохранить исходное соотношение сторон;
- не растягивать видео;
- использовать `object-fit: cover` только если обрезка не удаляет важные элементы;
- если важные детали находятся у краёв, использовать `object-fit: contain` или адаптивную композицию;
- исключить layout shift за счёт заранее заданного `aspect-ratio`.

---

## 6. Мобильная адаптация

Проверить как минимум:

```text
320 px
375 px
390 px
768 px
1024 px
1440 px
```

На мобильных устройствах:

- видео не выходит за границы экрана;
- нет горизонтального скролла;
- высота блока не становится чрезмерной;
- основные детали видео остаются видимыми;
- кнопка звука доступна пальцем и не перекрывает важный контент;
- используются `playsInline` и muted autoplay;
- при медленном соединении сначала показывается постер;
- мобильная версия не должна скачивать desktop-файл, если добавлен отдельный мобильный источник.

Если исходное горизонтальное видео плохо смотрится на телефоне, не обрезать его автоматически до вертикального формата без проверки. Предпочесть:

1. отдельный mobile-export;
2. аккуратный контейнер с исходным соотношением сторон;
3. только затем — контролируемый `object-fit: cover`.

---

## 7. Производительность

### 7.1. Загрузка

Использовать ленивую и условную загрузку:

- не инициировать тяжёлую загрузку видео до приближения блока к viewport;
- можно использовать `IntersectionObserver`;
- не добавлять стороннюю библиотеку только ради этого;
- постер должен загружаться раньше видео;
- не устанавливать `preload="auto"`.

### 7.2. Размер production-сборки

После реализации проверить:

- исходный мастер-файл не попал в `dist/`;
- в `dist/` находятся только оптимизированные версии;
- размеры MP4/WebM соответствуют разумным значениям;
- сборка не содержит дубликатов видео;
- медиа отдаётся с корректным MIME type.

### 7.3. Кэширование

У проекта уже настроено кэширование медиа через host-level Nginx.

Не менять Nginx-конфигурацию без необходимости.

После деплоя проверить заголовки:

```bash
curl -I https://снк-девелоперскийпроект.рф/video/sk-develop.mp4
curl -I https://снк-девелоперскийпроект.рф/video/sk-develop.webm
```

Проверить:

- HTTP 200;
- корректный `Content-Type`;
- присутствие ожидаемого `Cache-Control`;
- поддержку range-запросов, если её обеспечивает текущий Nginx.

## 8. Работа с исходным видео

Перед изменением кода:

1. найти видео в проекте или предоставленной папке;
2. определить:
   - фактический размер;
   - длительность;
   - разрешение;
   - fps;
   - кодеки;
   - наличие аудиодорожки;
   - ориентацию;
3. сообщить найденные параметры в итоговом отчёте;
4. подготовить оптимизированные варианты;
5. не удалять исходник вне репозитория;
6. не коммитить исходный тяжёлый файл.

Для анализа можно использовать:

```bash
ffprobe
```

Для конвертации можно использовать:

```bash
ffmpeg
```

Пример команды не считать обязательным решением — подобрать параметры по фактическому исходнику.

## 9. Интеграция

Перед реализацией найти:

- компонент главной страницы;
- компоненты секций «Ценность актива» и «Концепция»;
- фактический порядок их рендера;
- используемый контейнер и отступы;
- существующие анимации появления секций.

Добавить новый компонент строго между нужными секциями.

Не менять порядок остальных блоков.

Если на сайте уже используется общий механизм анимаций или Intersection Observer, переиспользовать его вместо создания дублирующей логики.

## 10. Доступность

Обеспечить:

- понятный `aria-label` для кнопки звука;
- управление кнопкой с клавиатуры;
- видимый focus-state;
- отсутствие обязательного звука;
- отсутствие агрессивного мигания;
- корректное поведение при отключённом autoplay;
- fallback-текст внутри `<video>`.

Если видео несёт только декоративную функцию, не добавлять лишнее текстовое описание.

Если видео содержит смысловую информацию, которая отсутствует на странице, указать это в итоговом отчёте и предложить текстовую альтернативу.

## 11. Проверки

### 11.1. Локально

Выполнить:

```bash
npm install
npm run build
npm run preview
```

Проверить:

- production-сборка проходит;
- новый блок отображается в правильном месте;
- видео запускается без звука;
- звук не включается автоматически;
- кнопка звука работает, если она реализована;
- видео не перезапускается хаотично при небольшом скролле;
- отсутствуют ошибки в Console;
- отсутствуют 404 для видео и постера;
- соседние блоки не изменились;
- мобильная версия работает корректно.

### 11.2. Docker

Выполнить:

```bash
docker build -t sk-develop .
docker run --rm -p 8080:80 sk-develop
```

Проверить:

```bash
curl -I http://localhost:8080/
curl -I http://localhost:8080/video/sk-develop.mp4
curl -I http://localhost:8080/video/sk-develop.webm
```

### 11.3. Браузеры

Проверить минимум:

- Chrome desktop;
- Safari desktop;
- Chrome Android или эмуляция;
- Safari iPhone или эмуляция.

## 13. Критерии готовности

Задача считается выполненной, если:

- [ ] новый видеоблок находится между секциями «Ценность актива» и «Концепция»;
- [ ] существующий дизайн вне нового блока не изменён;
- [ ] используется видео, а не GIF;
- [ ] исходный тяжёлый файл не попал в production и Git;
- [ ] доступны WebM и MP4 либо обоснованно оставлен один совместимый формат;
- [ ] есть оптимизированный постер;
- [ ] autoplay работает только без звука;
- [ ] музыка не включается автоматически;
- [ ] при наличии музыки есть явное управление звуком;
- [ ] видео загружается лениво или только при приближении к viewport;
- [ ] учтён `prefers-reduced-motion`;
- [ ] мобильная версия проверена;
- [ ] нет горизонтального скролла и layout shift;
- [ ] `npm run build` проходит успешно;
- [ ] Docker-сборка проходит успешно;
- [ ] нет ошибок Console и 404;
- [ ] обновлена проектная документация;
- [ ] создан Git-коммит;
- [ ] в итоговом отчёте перечислены изменённые файлы, размеры видео и результаты проверок.
